# Matchroom

An AI match desk that shows its working.** Matchroom turns a live stream of synthetic football
events into explainable match intelligence, real-time narratives, automated recaps and
personalised fan experiences. Built for the *Inside the Game: Developer Hackathon*.

Live demo: https://justtrying652.github.io/matchroom/ (replays feeds pre-generated by the real pipeline)
Demo video:

> **All data is synthetic.** Clubs, players, venue and results are fictional. No real Premier
> League data, names or logos are used.

## What it does

Matchroom covers the five stages of the challenge pipeline:

1. **Ingest:** a generator simulates a full match (about 1,500 events: passes with distance and
   difficulty, shots with xG and speed, tackles, pressure, sprints, cards, corners, possession changes).
2. **Interpret:** live stats, a rolling momentum index, and control-versus-chaos and rhythm readings.
3. **Explain:** a detector finds goals, big chances, momentum swings, pressure and control phases.
   Each moment carries the IDs of the exact events that prove it.
4. **Render:** every insight becomes a timed, machine-readable overlay card (layer, in/out time,
   colour, priority, evidence), shown in a live web match desk.
5. **Personalise:** casual or analyst depth, English or Kiswahili, favourite-club boost, and a
   player-focus mode.

## The agents

| Agent | Role |
|---|---|
| Analyst | Works out *why* a moment matters, from numbers only (no model) |
| Narrator | Writes the on-screen line for a given fan view (language model) |
| Verifier | Deterministic fact-checker: checks every claim, number and player name against the data |
| Recap Writer | Writes the full-time recap, checked by the same Verifier |
| Personalizer | Decides which moments each fan sees |

If a draft fails verification, the Verifier returns the exact problems and the Narrator rewrites it.
If the model keeps failing, a safe template takes over, so nothing unverified reaches the screen.
Click **Why?** on any card to see the evidence, the facts the writer was given, the Analyst's
reasoning, the Verifier's rejection log, and the overlay JSON.

**Honest limits:** the Verifier checks names, numbers and claimed fields. It does not judge every
nuance of wording, so a fluent sentence can still be loosely phrased.

## Run it

Python 3.10+.

```
pip install -r requirements.txt
python scripts/generate_match.py            # writes the synthetic match
python -m uvicorn matchroom.api:app --app-dir src --port 8000   # live version at http://localhost:8000
```

With no model configured, commentary comes from offline templates. To use a model, set
`GROQ_API_KEY` and `GROQ_MODEL` (any OpenAI-compatible model on Groq). Finished feeds are cached in
`data/feeds/`, so replays need no model calls.

Static (hosted) version: `python scripts/export_static.py` writes `docs/`, which GitHub Pages serves.

## Technology

GitHub (source and Pages hosting), Python, FastAPI with Server-Sent Events, vanilla JavaScript UI,
and an open-weight language model (gpt-oss-120b) served by Groq. An Azure OpenAI adapter is
included in `src/matchroom/llm.py` but has not been tested against a live deployment.
